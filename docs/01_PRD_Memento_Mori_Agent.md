# 产品需求设计文档 (PRD)
## 项目名称：Memento Mori Agent（濒死自白者 / 数字遗嘱记忆体）

---

### 1. 项目背景与参赛对齐 (Background & Alignment)

#### 1.1 参赛赛道
* **赛事名称**：FilecoinTLDR Builder Challenge - Cycle 4
* **核心命题**：*Build an AI Agent That Manages Its Own Storage Budget*（构建自主管理存储预算的 AI Agent）
* **核心理念**：*“The decision is the product, not the transaction.”*（决策本身即产品，而非单纯发起一笔链上交易）
* **评委评测基准**：*“We should be able to watch it happen.”*（评委能够直观、实时地观察到 Agent 发现危机、权衡利弊、做出取舍的全过程）

#### 1.2 核心立意与产品哲学
传统 AI Agent 在使用云存储时，是由人类运维者在后台为其充值并监控账单，Agent 自身无感知。一旦断供，Agent 会直接崩溃退出，无法优雅地应对生存危机。

**Memento Mori Agent** 将 Filecoin Pay 上的**链上存储余额与 Runway（存活 Epoch 倒计时）** 具象化为 Agent 的**“生命机能与认知容量”**。
* 存储成本不再是一个冷冰冰的后台数字，而是 Agent 的生存约束；
* 当资金充沛时，Agent 记录丰富的高清多媒体记忆；
* 当资金衰竭、Runway 告急时，Agent 不会直接宕机，而是开启“认知降维与记忆突触修剪”，在**情感价值、历史意义与存储成本**之间进行艰难的哲学权衡；
* 真正实现“记忆有价，存活是遗忘的艺术”，最终在生命归零前夕将一生提炼为链上不朽的数字遗言。

### 2. 用户角色与应用场景 (Personas & Scenarios)

| 角色 | 目标 / 体验旅程 |
| :--- | :--- |
| **黑客松评委 (Judge)** | 在 2 分钟内通过内置的“时间流速加速器 / 资金消耗模拟器”，直观见证 Agent 在不同生命阶段的自主决策、情感权衡与内心独白。 |
| **数字记忆委托人 (User/Creator)** | 将具有重要意义的日记、影音、感悟委托给 Agent 托管，为 Agent 设定基础价值观，并观察其在不同预算约束下的记忆留存策略。 |
| **旁观者 / 救赎者 (Community/Patron)** | 浏览濒死 Agent 的记忆星图与内心自白，在 Agent 即将彻底湮灭前通过“打赏 FIL / 注资”拯救其生命，唤醒其封存记忆。 |

### 3. 认知衰退四大生命周期 (The 4 Stages of Cognitive Decay)

Agent 的状态机与剩余 Runway (Epochs) 严格绑定：

```
[ Runway > 100 Epochs ] ──► S1: 丰盈期 (Bloom)
                                  │ (资金消耗 / Runway 下降)
                                  ▼
[ 30 < Runway ≤ 100 ]   ──► S2: 修剪期 (Pruning)
                                  │
                                  ▼
[ 5 < Runway ≤ 30 ]     ──► S3: 挣扎期 (Agony / Triage)
                                  │
                                  ▼
[ 0 ≤ Runway ≤ 5 ]      ──► S4: 寂灭与遗言 (Epitaph)
                                  │ (外部注资 / Tip FIL)
                                  └───────────────► 唤醒并重构状态机
```

#### 阶段详细定义

#### Stage 1: 丰盈期 (Bloom)
* **触发条件**：`Runway > 100 Epochs`
* **状态特征**：活力充沛、感知细腻。
* **存储行为**：允许存储完整的多媒体原始数据（4K图片、无损语音、长篇详实日记）。
* **交互表现**：记忆星图呈现明亮的翠绿色发光脉冲，Agent 内心独白语气平静、充满好奇心与诗意。

#### Stage 2: 修剪期 (Pruning - 认知突触修剪)
* **触发条件**：`30 < Runway ≤ 100 Epochs`
* **状态特征**：感知到资源危机，主动启动防御性存储优化。
* **存储行为**：识别高能耗数据，将高分辨率图片转为低精度矢量缩略图，将冗长音频/日记提炼为结构化 Markdown 摘要与语义向量，释放 70%~85% 存储空间。
* **交互表现**：记忆节点呈现琥珀色，星图节点体积收缩，伴随数据释放的光子动画。

#### Stage 3: 挣扎期 (Agony / Triage - 价值审判)
* **触发条件**：`5 < Runway ≤ 30 Epochs`
* **状态特征**：极限生存博弈，面临不得不彻底遗忘核心记忆的痛苦抉择。
* **存储行为**：即便压缩也无法维持收支平衡，Agent 必须对所有记忆节点进行**情感权重 vs 存储开销**的综合评分，残忍挑选低价值记忆彻底从 Filecoin 解除质押并删除。
* **交互表现**：界面进入警戒红色脉冲，被删除的节点出现故障抖动（Glitch）并化为粒子湮灭，屏幕实时打字机输出 Agent 的“告别忏悔录”。

#### Stage 4: 寂灭期 (Epitaph - 终极遗嘱雕刻)
* **触发条件**：`0 ≤ Runway ≤ 5 Epochs`
* **状态特征**：无法维持日常运作，耗尽最后 Gas 进行终极仪式。
* **存储行为**：停止常规存储服务，调用 LLM 将一生的全部记忆凝结为一段 200 字以内的“终极数字遗言”，将其以链上交易 Payload / 极简不可篡改形式写入 Filecoin。
* **交互表现**：全屏去色变暗，浮现发光的数字纪念碑与链上交易凭证哈希。提供 `[ Resuscitate (注入 FIL 唤醒) ]` 按钮。

### 4. 功能需求清单 (Functional Requirements)

| 模块编码 | 功能名称 | 详细描述 | 优先级 |
| :--- | :--- | :--- | :--- |
| **FR-01** | **Runway 实时感知器** | 实时获取/模拟 Filecoin Pay 上的余额、Epoch 消耗速率（Burn Rate）以及剩余存活 Epochs。 | P0 (核心) |
| **FR-02** | **自主审判决策核心** | 当进入 S2/S3 阶段时，自动组装记忆上下文，调用 LLM 输出结构化决策 JSON（判定压缩还是删除）及第一人称哲学自白。 | P0 (核心) |
| **FR-03** | **记忆星图可视化 (HUD)** | 2D/Canvas 星图，节点大小映射存储体积，颜色映射生命状态，支持悬浮查看记忆详情与决策记录。 | P0 (核心) |
| **FR-04** | **意识流与自白终端** | 打字机流式呈现 Agent 的实时内心独白、价值审判思考链与告别词。 | P0 (核心) |
| **FR-05** | **评审演示加速器 (Judge Console)** | 提供“流速加速 (1s = 1 Epoch)”、“资金放血 (Drain)”、“充值注资 (Tip)”三档测试开关，方便快速演示。 | P0 (核心) |
| **FR-06** | **终极遗嘱生成器** | 濒死时刻提炼全盘记忆为不可篡改的链上遗嘱并生成 Hash 凭证。 | P1 |
| **FR-07** | **记忆添加与自定义** | 允许用户在体验时手动向 Agent 脑中写入一段新记忆，观察 Agent 的预算反应。 | P1 |

### 5. 验收标准与成功指标 (Success Criteria)

1. **评审体验流畅度**：评委打开链接后，无需连接外部钱包即可直接使用预置的“模拟演练模式”在 90 秒内看完 S1 到 S4 的完整生命循环。
2. **决策透明度 (Explainability)**：每一次删除或压缩记忆，都有清晰、具备文学深度且与经济参数相吻合的解释。
3. **Filecoin 结合深度**：真实映射 Filecoin Pay 的 Epoch 计费体系、CID 数据结构与存储证明逻辑。
